# Lightbox — Asset Review Tool

## What This Is

Lightbox is a browser-based internal tool for Jason to review assets generated by overnight agent sessions. Agents generate pixel art via PixelLab MCP (characters, objects, animations), and Jason needs to quickly preview everything, approve or reject it, and leave notes — all without opening individual files in ASEprite or navigating the filesystem.

The name comes from the photography lightbox: a surface you lay transparencies on to quickly compare and evaluate visual work.

## The Problem It Solves

An overnight Ralph loop might generate 10-20 assets across multiple PixelLab calls. Some will be good, some bad, some close-but-need-tweaks. Right now there's no fast way to:

1. See everything that was generated in one place
2. Preview assets the way they'll actually be used (animated, directional, static)
3. Record which are approved, rejected, or need changes
4. Feed those decisions back to the next agent session

The existing `workshop/pixellab/viewer.html` handles basic preview but has no review workflow — no status tracking, no output file for agents.

## What It Is NOT

- Not a game engine or runtime preview. Assets are shown in isolation, not in-game context.
- Not an interactive approval UI with buttons. Jason reviews by looking at the page and speaking to Claude via voice-to-text. The page is display-only.
- Not a bridge. Bridges are for AI agents to verify correctness. Lightbox is for human eyes.

## Three Preview Modes

Every generated asset falls into one of three categories, each needing its own preview treatment:

### 1. Static Image
A single sprite or object (e.g., `002-slime-map-object/slime.png`). Display it at multiple zoom levels (1x, 4x, 8x) with pixelated rendering. Show on both dark and light backgrounds so transparency is visible.

### 2. Directional Set
A character with 4 or 8 rotations (e.g., `001-slime-humanoid-character/rotations/*.png`). Display all directions in a compass-style layout so you can see consistency across views. Optionally cycle through them to simulate a turning character.

### 3. Animation Loop
A sequence of frames meant to play as a loop (e.g., `003-slime-idle-tiles/frame_*.png`). Play at the intended frame rate with controls for speed, pause, frame scrubbing. Show the full filmstrip below so individual frames are visible.

## Data Source

Lightbox reads from `workshop/pixellab/manifest.json` (built by `build-manifest.ts`). The manifest already tracks experiment ID, name, frames, and notes. It would need to be extended with:

- **`type`**: `"static" | "directional" | "animation"` — determines which preview mode to use
- **`status`**: `"unreviewed" | "approved" | "rejected" | "needs-changes"` — review state
- **`review_notes`**: Free-text notes from Jason's review (e.g., "too humanoid, redo as blob")
- **`direction_map`** (directional only): Which frame maps to which direction (e.g., `{"south": "rotations/south.png", ...}`)
- **`frame_rate`** (animation only): Intended playback speed in ms per frame

The `build-manifest.ts` script should infer `type` from directory structure (has `rotations/` → directional, has `frame_*.png` → animation, single image → static) but allow manual override in a per-experiment `config.json`.

## Review Workflow

1. Agent runs overnight, generates assets, runs `build-manifest.ts` to update manifest
2. Morning: Jason opens Lightbox in browser (`npx serve workshop/lightbox` or similar)
3. Page shows all assets with `status: "unreviewed"` prominently, approved/rejected dimmed
4. Jason scrolls through, previewing each asset in its appropriate mode
5. Jason opens Claude, uses voice-to-text: _"wolf-angry looks bad, shopkeep-idle looks good, wooden-bridge needs more contrast on the edges"_
6. Claude reads the conversation, updates `manifest.json` with status and review_notes for each referenced asset
7. Next overnight agent session reads `manifest.json`, knows which assets to regenerate and what to change

## Output Contract

The review state lives in `manifest.json` as extended fields on each experiment entry. Agents read this to determine:

- **`"approved"`** — Asset is final. Move to `src/assets/` or wherever production assets live.
- **`"rejected"`** — Redo from scratch. Original prompt/settings didn't work.
- **`"needs-changes"`** — Close but needs specific adjustments. `review_notes` explains what.
- **`"unreviewed"`** — Agent hasn't gotten human feedback yet. Don't use in production.

## Page Layout

Minimal. No framework. Single HTML file with inline CSS/JS (same pattern as `viewer.html`).

- **Header**: Asset count summary (e.g., "3 unreviewed, 5 approved, 2 rejected")
- **Filter bar**: Show all / unreviewed only / needs attention
- **Asset cards**: Grid of cards, each showing:
  - Asset name and experiment ID (large, readable — Jason references these by name in voice review)
  - Preview appropriate to type (static/directional/animation)
  - Current status badge
  - Review notes if any
- **Detail view**: Click a card to see full-size preview with all controls

## Relationship to Existing viewer.html

The existing `workshop/pixellab/viewer.html` is a prototype that handles basic grid + animation preview. Lightbox replaces it by adding:

- Asset type detection and appropriate preview mode
- Review status tracking
- Manifest extensions for review workflow
- Better organization (unreviewed assets prominent)

The viewer.html can be retired once Lightbox is functional.

## Future Scope (Not Now)

- Audio preview for SFX assets (play/stop, waveform display)
- Map preview for Tiled JSON assets (rendered tile grid)
- Side-by-side comparison (old version vs new version after regeneration)
- Batch operations (approve all in a set)
